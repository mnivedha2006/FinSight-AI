## The problem

UPI makes payments instant, and that makes scams instant too. Three patterns are hard to catch with a single model:

- **Fake collect requests.** The amount looks ordinary, so a transaction-only model sees nothing wrong.
- **Phishing SMS in regional languages.** A text-only model never sees the payment that follows.
- **Mule beneficiaries.** Many victims pay the same new account, which only shows up when you look at who pays whom.

FinSight AI scores each payment from three independent signals, combines them into one score, and shows an investigator exactly why.

## What it does

- **One score, three kinds of evidence.** Behaviour (how unusual the payment is), message (scam wording in the linked SMS), and network (very young beneficiary, many first-time senders, shared devices) are fused into a 0 to 100 risk score with a decision: approve, review or block.
- **Evidence you can read.** For every payment, the dashboard shows how much each signal pushed the decision.
- **Counterfactual lab.** Change one thing about a payment (the beneficiary is known, the message was never sent, the amount is smaller) and the whole pipeline is re-run. Nothing is subtracted by hand.
- **Grounded explanations.** A rule-based summary built only from the payment's own evidence, with an optional Gemini rewrite in English, Tamil or Hindi. Any number the model writes that is not in the evidence causes the reply to be rejected.
- **Message scanner.** Paste an SMS, or upload a CSV, in English, Tamil or Hindi (script and romanised). A line such as "never share your OTP" is recognised as a safety warning, not as a scam signal.
- **Spending insights and beneficiary network** for any account or beneficiary.

## How it works

| Signal | Method | What it looks at |
|---|---|---|
| Behaviour | Isolation Forest | Amount against the account's usual amount, speed, timing, share of balance, new beneficiary |
| Message | TF-IDF (word and character n-grams) + logistic regression + scam rules | Urgency, OTP and PIN requests, look-alike links, collect-request wording |
| Network | Indicators computed from the ledger | Beneficiary under 15 days old, many first-time senders, accounts sharing a device that pay the same beneficiary |

**Fusion.** A logistic regression over the three signals. Weights are fitted on a 60% train split, the review threshold is chosen on a 20% validation split, and results are reported on the untouched 20% test split. Fraud labels are used only for this fitting and for evaluation; they never enter a signal.

**Message scoring is out-of-family.** Every message used in fusion is scored by a model that never saw that message's family of templates, so the message signal is not inflated by memorisation.

**The 0 to 100 score** is a monotone rescaling of the fusion model's log-odds in which 40 is the review threshold. It is a risk indicator, not a calibrated probability of fraud.

## Results

**Held-out test split: 1000 payments, 50 fraud.** Synthetic data.

| Signal | Precision | Recall | F1 | PR-AUC |
|---|---|---|---|---|
| Behaviour only | 0.67 | 0.58 | 0.62 | 0.64 |
| Message only | 0.78 | 0.28 | 0.41 | 0.37 |
| Network only | 0.89 | 0.92 | 0.90 | 0.95 |
| Fusion | 0.89 | 0.96 | 0.92 | 0.99 |

The behaviour model flags 0% of suspicious collect requests because their amounts look ordinary; the message and network signals catch them, and fusion flags 100%.

On legitimate large payments and shopping bursts (23 in the test split), the behaviour model raises a false alarm 30% of the time; fusion 0%.

The scam-message classifier, tested on message families it never saw in training: precision 1.00, recall 0.69, F1 0.82.

## Limitations

Please read these before trusting any number above.

1. **All data is synthetic.** The results show that the pipeline works end to end, not real-world accuracy.
2. **The network signal is partly circular.** Mule beneficiaries were generated as very new accounts, and the network indicator looks for exactly that.
3. **Messages are linked to payments by the data generator** with fixed probabilities, which helps the message signal more than it would in practice.
4. **The test split is small** (about 50 fraud cases), so per-fraud-type figures are noisy.
5. **Message families are parallel across languages**, so Tamil and Hindi results benefit from the same scenarios appearing in English.
6. **Splits are random across payments, not across accounts.**

The full list, with tables, is in the [evaluation report](evaluation/EVALUATION_REPORT.md).

## Run it yourself

The repository already contains the generated data and trained models, so the dashboard runs straight away.

```bash
git clone https://github.com/mnivedha2006/FinSight-AI.git
cd FinSight-AI
python -m venv venv
venv\Scripts\activate          # macOS and Linux: source venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

To rebuild everything from scratch (data, features, models, fusion, report):

```bash
python run_pipeline.py
```

To run the tests (data integrity, leakage guards, counterfactual and explainer checks, and every dashboard page and theme):

```bash
pip install pytest
python -m pytest -q
```

**Optional: AI explanations.** Create `.streamlit/secrets.toml` containing `GEMINI_API_KEY = "your-key"`. Without a key the dashboard shows the rule-based explanation. Only synthetic data is ever sent to the API.

## Project structure

```
app.py                      Streamlit dashboard
run_pipeline.py             Rebuilds data, models, fusion and the report in order
data_generation/            Synthetic payments, accounts, beneficiaries and messages
intelligence/
  feature_engineering.py        Payment features
  message_rules.py              Scam rules and text normaliser, shared everywhere
  risk_fusion.py                Combines the three signals
  counterfactual.py             Re-runs the whole pipeline after a what-if
  explainer.py                  Rule-based and Gemini explanations with a grounding check
models/                     Training scripts and saved models
graph/                      Network summary
evaluation/                 Metrics, report generator, EVALUATION_REPORT.md
tests/                      pytest suite
assets/                     Architecture diagram
```

## Built with

Python, pandas, NumPy, scikit-learn, Plotly, Streamlit, joblib, NetworkX and pytest. Optional: the Google Gemini API (`gemini-2.5-flash`) for explanation rewrites. Dashboard font: Schibsted Grotesk (Google Fonts).
